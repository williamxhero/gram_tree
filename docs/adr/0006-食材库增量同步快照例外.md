# 0006 食材库增量同步快照例外

- 状态：已采纳（2026-09-30，SPEC-002.1 #101）
- 背景：ADR-0002 规定用户可浏览的列表接口统一使用游标分页；食材库同步是客户端缓存协议，不是用户可浏览列表。

## 决定

`GET /v1/ingredients/changes` 返回客户端指定版本之后的完整同步快照，包含 `added`、`modified`、`merged` 和 `releases` 四组集合，不使用通用 `{items, next_cursor}` 列表形状。首次同步不带版本号时也返回完整食材库，保证客户端可以原子地建立本机缓存。

这是对 ADR-0002“列表一律游标分页”的明确协议例外，而不是对普通列表接口的豁免。若未来食材库规模可能超过单次同步响应上限，必须新增带游标的同步契约并同步修改客户端，不能静默改变现有响应语义。

## 依据

- #101 的验收要求是“返回那之后的全部变化”，首次下载要求返回整份食材库。
- 客户端增量同步必须在一次成功响应后原子替换缓存；把四组集合拆成独立列表页会使版本提交和失败恢复变得不一致。
- 搜索和未收录统计等用户可浏览列表仍严格遵守 ADR-0002 的游标分页约定。
