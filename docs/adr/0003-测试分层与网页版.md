# 0003 测试分层，以及网页版只作为测试目标

- 状态：已采纳（2026-09-27，SPEC-013.1 #15）
- 背景：用户要求测试尽量用安卓，但只在用到手机能力的地方用；网页版做全面的功能测试；iOS 和真机由用户自己测。实测云端开发容器没有 KVM，跑不了安卓模拟器，`dl.google.com` 也被网络策略拦住。

## 决定

原则：只测外部行为。服务端只通过对外接口（HTTP、命令行）测；App 只看页面显示和操作结果。

| 层 | 内容 | 在哪跑 | 样板 |
|---|---|---|---|
| 1 服务端接口测试 | 连真 PostgreSQL（含 pgvector）和 Redis；整轮开始时重建测试库、跑完全部迁移；每个测试后清空业务表；AI 调用用录制回答（SPEC-003.1 加） | 云端线程 + CI `server` | `server/tests/conftest.py` |
| 2 页面测试 | 用生成的接口模型构造假数据，覆盖浅色、深色、大字号 | 云端线程 + CI `app`（VM 和 `--platform chrome` 各跑一遍） | `app/test/helpers.dart` |
| 3 网页版端到端 | `integration_test` 编译成网页，在无界面 Chromium 里跑完整流程 | 云端线程 + CI `web-e2e` | `tool/web_test.sh`、`app/integration_test/` |
| 4 安卓模拟器端到端 | 只覆盖网页测不到的手机能力（锁屏计时和通知、分享进 App、相机、离线本地库、后台同步） | 只在 CI `android-e2e`（GitHub 的 Linux 机器有 KVM） | 同一份 `integration_test` |
| 5 iOS 模拟器 | 按需 | CI `ios-e2e`，手动触发（workflow_dispatch） | 同上 |
| 6 真机 | 用户自己安排 | 用户手机 | 每个 PR 正文列“需要真机测试的点” |

### 客户端必须能编译成网页版

- 手机专有能力放在接口后面（`app/lib/platform/device_capabilities.dart`），手机端用真实实现，网页端用替身，页面代码只依赖接口。新增手机能力照这个模式加。
- 网页版不对外发布，只是测试目标。
- CI 里 `flutter build web` 编译不过就失败。

### 网页端到端的坑

- `flutter drive` 必须用 `--profile`：debug 模式下结果回不来，会卡到超时。
- 加 `--no-web-resources-cdn`，不从 Google CDN 拉渲染引擎。
- 云端以 root 运行，Chromium 要加 `--no-sandbox`；chromedriver 主版本要和 Chromium 一致。会话启动钩子会在 `/opt/gramtree-tools/bin` 放好包装脚本 `google-chrome` 和同版本 `chromedriver`。
- 云端没有网络字体，截图里中文会是方框；这不影响按文字查找控件的测试。
