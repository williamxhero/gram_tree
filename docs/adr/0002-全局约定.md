# 0002 接口和数据的全局约定

- 状态：已采纳（2026-09-27，SPEC-013.1 #15）
- 示例：`server/gramtree/examples/router.py`（只在非正式环境挂载）是这些约定的参考写法，测试在 `server/tests/test_conventions.py`。

| 约定 | 做法 | 代码 |
|---|---|---|
| 接口版本 | 全部挂在 `/v1` 下；不兼容的改动开 `/v2` 并存一段时间 | `gramtree/main.py` |
| ID | 对外 ID 一律随机 UUID v4；离线创建的数据由客户端生成同样格式的 ID，服务端校验格式（`IdV4`）并按 ID 去重（重复提交返回已有记录） | `gramtree/core/ids.py` |
| 时间 | 接口里带时区的 ISO 8601（`Timestamp`，输出为 UTC）；数据库列 `timestamptz`，按 UTC 存 | `gramtree/core/time.py`、`gramtree/db.py` |
| 错误格式 | `{"error": {"code", "message", "detail", "request_id"}}`：code 给程序判断，message 给用户看，detail 给开发者看。业务代码抛 `ApiError` 子类，不自己拼响应；未处理的异常也转成这个格式 | `gramtree/core/errors.py`、`gramtree/core/middleware.py` |
| 请求编号 | 每个请求一个 `X-Request-ID`（客户端带了合法 UUID 就沿用），写进响应头、错误体和每条日志 | `gramtree/core/request_context.py` |
| 日志 | 每行一个 JSON，带请求编号；访问日志带路径、状态码、耗时 | `gramtree/core/logging.py` |
| 分页 | 列表一律游标分页：`?cursor=&limit=`，返回 `{items, next_cursor}`；`limit` 上限是配置项 `api.page_size_max`，超过返回 422。游标签名和有效期在 SPEC-011.2 加 | `gramtree/core/pagination.py` |
| 服务端配置项 | 在 `runtime_config/registry.py` 登记 key、类型、默认值、取值范围、说明；数据库只存改过的值；每次读都查库，改完立刻生效；只能用命令行 `gramtree config set <key> <value> --by <人> --reason <原因>` 修改，留历史 | `gramtree/runtime_config/` |
| 能力开关 | 配置项里 `feature.*` 开头、`public=True` 的项，经 `GET /v1/client-config` 下发；App 用 `FeatureGate` 包住入口，关闭或拉取失败时不显示。底部五入口固定，不受开关控制 | `gramtree/api/client_config.py`、`app/lib/features_flags/features.dart` |
| 进程级设置 | 部署时决定、运行中不变的东西（数据库地址、SMTP 等）用 `GRAMTREE_*` 环境变量，见 `server/.env.example` | `gramtree/settings.py` |
